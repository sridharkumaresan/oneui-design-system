Implementation mindset:
Think like a senior enterprise web architect. Do not create a flat prototype. Create a foundation where future features can be added cleanly.

The first feature is only the home dashboard, but the app should be ready for future features such as:
- Domains management
- Entitlements management
- Roles management
- User groups management
- Relationship management
- Reports
- Audit history
- Access request workflows
- Approval queues
- User access profile
- Admin configuration
- Search results page
- Detail pages

Architecture principles:
- Separate app shell from feature modules.
- Separate domain models from UI models if needed.
- Keep service contracts independent from mock or HTTP implementation.
- Use dependency injection/light composition through providers or factory functions.
- Keep mock data outside UI components.
- Keep configuration outside UI components.
- Make quick actions, tabs, widgets, and dashboard table data-driven.
- Use strongly typed config objects.
- Use clear barrel exports where appropriate.
- Avoid circular dependencies.
- Avoid hardcoded business data inside presentational components.
- Keep components small and composable.
- Prefer controlled props and explicit event handlers.
- Avoid over-engineering but design for growth.

Required service pattern:
Create a service contract:

interface IHueDashboardService {
  getDashboard(): Promise<HueDashboardViewModel>;
  search(query: HueSearchQuery): Promise<HueSearchResult[]>;
}

Create two implementations:

1. MockHueDashboardService
- Uses local mock JSON/static TypeScript mock data.
- Used for standalone local development initially.

2. HttpHueDashboardService
- Uses a generic ApiClient.
- Does not need real endpoints now.
- Should be ready for future HTTP API integration.
- Endpoint paths should come from config, not be hardcoded inside components.

Create an environment/config switch:

dataSource: "mock" | "http"

The app should use mock mode by default.

Optional local API:
If the workspace supports it, prepare a json-server-compatible db.json under:

src/data/json-server/db.json

Do not require json-server for the app to run. It should be optional.
